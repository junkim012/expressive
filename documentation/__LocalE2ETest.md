# Local E2E Test

## Goal

Run the full stack locally against a live Anvil chain to verify that:
- The contract executes correctly
- The backend indexes all events correctly
- The frontend displays accurate state from the backend

The local frontend deployment won't work without a local backend deployment. The local backend deployment won't work without a local anvil contract deployment. So these tests must be executed together.

---

## Architecture

```
Anvil (localhost:8545)
    ↑  eth_getLogs / eth_sendRawTransaction
Backend (localhost:3001)
    ↑  REST + WebSocket
Frontend (localhost:3000)
```

---

Shell scripts, scenario scripts, and generated env files all live under `e2e/`. The Solidity deploy script lives in `contracts/script/` — that is where forge reliably resolves imports and remappings. The `02_deploy.sh` script `cd`s into `contracts/` before invoking forge, so from the outside everything is driven from `e2e/`.

## Step 2: Deploy Contracts

`e2e/LocalSetup.s.sol` deploys everything needed for local testing in a single broadcast. Forge resolves imports using `--root contracts`, so `src/ExpressiveLending.sol` maps to `contracts/src/`:

```solidity
// e2e/LocalSetup.s.sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import {Script, console} from "forge-std/Script.sol";
import {ExpressiveLending} from "src/ExpressiveLending.sol";
import {IOracle} from "src/IOracle.sol";
import {ERC20} from "openzeppelin-contracts/contracts/token/ERC20/ERC20.sol";

contract MockERC20 is ERC20 {
    uint8 private _dec;
    constructor(string memory n, string memory s, uint8 d) ERC20(n, s) { _dec = d; }
    function decimals() public view override returns (uint8) { return _dec; }
    function mint(address to, uint256 amt) external { _mint(to, amt); }
}

contract MockOracle is IOracle {
    uint256 public price;
    constructor(uint256 p) { price = p; }
    function setPrice(uint256 p) external { price = p; }
    function getPrice() external view returns (uint256) { return price; }
}

contract LocalSetup is Script {
    function run() external {
        address lender1   = 0x70997970C51812dc3A010C7d01b50e0d17dc79C8;
        address lender2   = 0x3C44CdDdB6a900fa2b585dd299e03d12FA4293BC;
        address borrower  = 0x90F79bf6EB2c4f870365E785982E1f101E93b906;
        address liquidator = 0x9965507D1a55bcC2695C58ba16FB37d819B0A4dc;

        vm.startBroadcast();

        // Deploy tokens
        MockERC20 usdc = new MockERC20("USD Coin",    "USDC", 6);
        MockERC20 wbtc = new MockERC20("Wrapped BTC", "WBTC", 8);
        MockERC20 weth = new MockERC20("Wrapped ETH", "WETH", 18);

        // Deploy oracles
        // price * collateralAmountWei / 10**collateralDecimals = USDC value
        MockOracle btcOracle = new MockOracle(80_000e6); // 80 000 USDC/BTC
        MockOracle ethOracle = new MockOracle(3_000e6);  //  3 000 USDC/ETH

        // Deploy protocol
        address[] memory collaterals = new address[](2);
        collaterals[0] = address(wbtc);
        collaterals[1] = address(weth);

        address[] memory borrows = new address[](1);
        borrows[0] = address(usdc);

        address[] memory oracles = new address[](2);
        oracles[0] = address(btcOracle);
        oracles[1] = address(ethOracle);

        ExpressiveLending protocol = new ExpressiveLending(
            30,     // batchWindowSeconds
            10,     // solverFeeRate (0.10% bps)
            500,    // liquidationBonusRate (5%)
            collaterals,
            borrows,
            oracles
        );

        // Fund participants
        usdc.mint(lender1,   10_000e6);
        usdc.mint(lender2,   10_000e6);
        usdc.mint(liquidator, 50_000e6);
        wbtc.mint(borrower,  5e8);       // 5 BTC
        weth.mint(borrower,  50 ether);

        vm.stopBroadcast();

        console.log("USDC       :", address(usdc));
        console.log("WBTC       :", address(wbtc));
        console.log("WETH       :", address(weth));
        console.log("BTC_ORACLE :", address(btcOracle));
        console.log("ETH_ORACLE :", address(ethOracle));
        console.log("PROTOCOL   :", address(protocol));
        console.log("START_BLOCK:", block.number);
    }
}
```

Run the deploy (from the repo root):

```bash
# e2e/02_deploy.sh
DEPLOYER_KEY=0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80

forge script e2e/LocalSetup.s.sol \
  --root contracts \
  --rpc-url http://localhost:8545 \
  --private-key $DEPLOYER_KEY \
  --broadcast \
  --json 2>/dev/null \
  | jq -r '.logs[] | select(.type == "log") | .message'
```

`--root contracts` tells forge where `foundry.toml`, `lib/`, and `remappings.txt` live. The script file path (`e2e/LocalSetup.s.sol`) is resolved from the current directory independently.

Capture the printed addresses and write them to `e2e/.env.local`:

```bash
# e2e/.env.local (generated; git-ignored)
RPC_URL=http://localhost:8545
CONTRACT_ADDRESS=0x...          # PROTOCOL address from forge output
START_BLOCK=1                   # or whichever block forge reported
SOLVER_FEE_RATE=10
DB_PATH=./data/local.db

USDC_ADDRESS=0x...
WBTC_ADDRESS=0x...
WETH_ADDRESS=0x...
BTC_ORACLE_ADDRESS=0x...
ETH_ORACLE_ADDRESS=0x...
```

## Test Scenarios

Run these in order. After each `cast send`, wait ~1–2 seconds for the backend poller tick, then verify via the API.

---

### Scenario 1: Place Orders

**Lender 1** places a lend order: 1 000 USDC, min rate 4% (400 bps), accepts WBTC and WETH collateral.

```bash
USDC_ADDR=<USDC_ADDRESS>
WBTC_ADDR=<WBTC_ADDRESS>
WETH_ADDR=<WETH_ADDRESS>

# placeLendOrder(borrowAsset, acceptableCollateral[], minRate, maxLtv, maxDuration, maxLltv, amount)
cast send $PROTOCOL \
  "placeLendOrder(address,address[],uint256,uint256,uint256,uint256,uint256)" \
  $USDC_ADDR \
  "[$WBTC_ADDR,$WETH_ADDR]" \
  400 \
  7000 \
  31536000 \
  8000 \
  1000000000 \
  --rpc-url http://localhost:8545 \
  --private-key $LENDER1_KEY
```

**Borrower** places a borrow order: wants 1 000 USDC, posts 1 BTC collateral, max rate 7% (700 bps).

```bash
# placeBorrowOrder(borrowAsset, collateralAssets[], collateralAmounts[], maxRate,
#                  minLtv, minDuration, minLltv, amount, fillOrKill)
cast send $PROTOCOL \
  "placeBorrowOrder(address,address[],uint256[],uint256,uint256,uint256,uint256,uint256,bool)" \
  $USDC_ADDR \
  "[$WBTC_ADDR]" \
  "[100000000]" \
  700 \
  5000 \
  15552000 \
  7000 \
  1000000000 \
  false \
  --rpc-url http://localhost:8545 \
  --private-key $BORROWER_KEY
```

**Verify backend:**

```bash
curl "http://localhost:3001/api/v1/orders?status=open" | jq '.orders | length'
# 2

curl "http://localhost:3001/api/v1/orders?type=lend" | jq '.[0] | {orderId, owner, minRate, filledAmount}'
# {"orderId":"0","owner":"0x70997...","minRate":400,"filledAmount":"0"}
```

**Verify frontend:** Order book shows one lend order and one borrow order.

### Scenario 2: Submit and Execute Batch

**Solver** submits a batch pairing the lend and borrow orders, then executes after the 30-second window.

```bash
SOLVER_KEY=0x47e179ec197488593b187f80a00eb0da91f1b9d0b13f8733639f19c30a34926b

# The lend order is orderId 0, borrow order is orderId 1 (assigned in placement order).
# Consumptions must be sorted by orderId ascending.

# submitBatch(pairs[], consumptions[])
# Pair: (lendOrderId, borrowOrderId, amount)
# Consumption: (orderId, totalConsumed)
cast send $PROTOCOL \
  "submitBatch((uint256,uint256,uint256)[],(uint256,uint256)[])" \
  "[(0,1,1000000000)]" \
  "[(0,1000000000),(1,1000000000)]" \
  --rpc-url http://localhost:8545 \
  --private-key $SOLVER_KEY
```

Verify the winning batch is recorded:

```bash
cast call $PROTOCOL "currentWinner()(address)" --rpc-url http://localhost:8545
cast call $PROTOCOL "currentBestSurplus()(uint256)" --rpc-url http://localhost:8545
# surplus = (700 - 400) * 1_000e6 / 10000 = 30_000_000 (30 USDC)
```

Advance Anvil time past the 30-second batch window:

```bash
cast rpc anvil_increaseTime 31 --rpc-url http://localhost:8545
cast rpc anvil_mine 1 --rpc-url http://localhost:8545
```

Execute the batch:

```bash
cast send $PROTOCOL "executeBatch()" \
  --rpc-url http://localhost:8545 \
  --private-key $SOLVER_KEY
```

**Verify contract state:**

```bash
cast call $PROTOCOL "getLoan(uint256)(address,address,address,uint256,uint256,uint256,uint256,uint256,uint8)" 0 \
  --rpc-url http://localhost:8545
# borrower=0x90F7..., lender=0x7099..., rate=550, status=0 (Active)
```

Rate = midpoint of 400 and 700 = 550 bps. Principal = 1 000 USDC − 0.10% fee = 999 USDC.

**Verify backend:**

```bash
curl "http://localhost:3001/api/v1/loans" | jq '.loans[0] | {loanId, rate, principal, status}'
# {"loanId":"0","rate":550,"principal":"999000000","status":"active"}

curl "http://localhost:3001/api/v1/orders?status=open" | jq '.orders | length'
# 0  (both orders are now filled)

curl "http://localhost:3001/api/v1/batches" | jq '.batches[0] | {windowId, solver, pairCount}'
# {"windowId":"0","solver":"0x15d3...","pairCount":1}
```

**Verify frontend:**
- Batch page: history shows window 0 with 1 pair matched and the solver address
- Positions panel (as lender): loan ID 0, rate 5.50%, active
- Positions panel (as borrower): loan ID 0, collateral health green
- Borrower wallet balance increased by ~999 USDC

### Scenario 3: Repay Loan

Borrower has received 999 USDC principal. They repay principal + accrued interest. Interest accrues in real time (Anvil mines blocks at 1s intervals), so mint a small buffer.

```bash
# Check accrued interest
cast call $PROTOCOL "getAccruedInterest(uint256)(uint256)" 0 --rpc-url http://localhost:8545

# Repay
cast send $PROTOCOL "repay(uint256)" 0 \
  --rpc-url http://localhost:8545 \
  --private-key $BORROWER_KEY
```

**Verify:**

```bash
cast call $PROTOCOL "getLoan(uint256)(address,address,address,uint256,uint256,uint256,uint256,uint256,uint8)" 0 \
  --rpc-url http://localhost:8545
# status = 1 (Repaid)

# Check borrower got BTC back
cast call $WBTC_ADDR "balanceOf(address)(uint256)" 0x90F79bf6EB2c4f870365E785982E1f101E93b906 \
  --rpc-url http://localhost:8545
# back to 5e8 (5 BTC)
```

**Lender redeems NFT** (tokenId 0, same as loanId 0):

```bash
cast call $PROTOCOL "ownerOf(uint256)(address)" 0 --rpc-url http://localhost:8545
# 0x70997... (lender1 holds the NFT)

cast send $PROTOCOL "redeem(uint256)" 0 \
  --rpc-url http://localhost:8545 \
  --private-key $LENDER1_KEY
```

Lender1's USDC balance should increase by principal + interest.

**Verify backend:**

```bash
curl "http://localhost:3001/api/v1/loans/0" | jq '.loan.status, .events'
# "repaid"
# [{...}]  — no repaid event since contract emits LoanRepaid
```

**Verify frontend:** Loan row moves to History section, status shows "Repaid".

### Scenario 4: Liquidation (LLTV Breach)

Create a new loan first (repeat Scenario 1 and 2 to get loan ID 1), then crash the BTC oracle price to make it undercollateralized.

```bash
# Drop BTC price from 80 000 USDC to 500 USDC (far below LLTV threshold)
cast send $BTC_ORACLE_ADDRESS "setPrice(uint256)" 500000000 \
  --rpc-url http://localhost:8545 \
  --private-key $DEPLOYER_KEY

# Verify loan is now unhealthy
cast call $PROTOCOL "isHealthy(uint256)(bool)" 1 --rpc-url http://localhost:8545
# false

# Liquidator takes all BTC collateral
# liquidate(loanId, collateralAssets[], collateralAmounts[])
LIQUIDATOR_KEY=0x8b3a350cf5c34c9194ca85829a2df0ec3153be0318b5e2d3348e872092edffba

cast send $PROTOCOL \
  "liquidate(uint256,address[],uint256[])" \
  1 \
  "[$WBTC_ADDR]" \
  "[100000000]" \
  --rpc-url http://localhost:8545 \
  --private-key $LIQUIDATOR_KEY
```

**Verify:**

```bash
cast call $PROTOCOL "getLoan(uint256)(...)" 1 --rpc-url http://localhost:8545
# status = 3 (Liquidated)

curl "http://localhost:3001/api/v1/loans/1" | jq '.loan.status, .events[0].eventType'
# "liquidated"
# "liquidated"
```

**Verify frontend:** Loan row shows "Liquidated" with liquidator address visible in the event log.

### Scenario 5: Post-Maturity Default

Create a third loan, then warp time past its maturity date and call `markDefaulted`.

```bash
# After creating loan 2 with minDuration = 180 days (15552000 seconds)...
# Get the loan's duration from contract to know exactly how far to warp
cast call $PROTOCOL "getLoan(uint256)(...)" 2 --rpc-url http://localhost:8545

# Warp past maturity (180 days + 1 second)
cast rpc anvil_increaseTime 15552001 --rpc-url http://localhost:8545
cast rpc anvil_mine 1 --rpc-url http://localhost:8545

# Anyone can call markDefaulted
cast send $PROTOCOL "markDefaulted(uint256)" 2 \
  --rpc-url http://localhost:8545 \
  --private-key $DEPLOYER_KEY
```

**Verify:**

```bash
cast call $PROTOCOL "getLoan(uint256)(...)" 2 --rpc-url http://localhost:8545
# status = 2 (Defaulted)

curl "http://localhost:3001/api/v1/loans/2" | jq '.loan.status'
# "defaulted"
```

## Common Issues

**Backend not picking up events:**
- Check `lastIndexedBlock` from `GET /health` — if it's stuck, look for RPC errors in the backend terminal
- Anvil with `--block-time 1` always has new blocks; the poller should advance every `POLL_INTERVAL_MS`

**`cast send` reverts with no message:**
- Add `--trace` flag to `cast send` to see the revert reason
- Common cause: forgot to approve tokens, or batch window still open

**Batch window timing:**
- `executeBatch` reverts with `WindowStillOpen` if called before `windowStart + 30s`
- Use `anvil_increaseTime` + `anvil_mine` to skip ahead; do not just wait — Anvil's real wall clock and `block.timestamp` can diverge

**Frontend wallet can't send transactions:**
- Import an Anvil private key into MetaMask and switch to the custom network (RPC `http://localhost:8545`, chain ID `31337`)
- MetaMask may cache a stale nonce after Anvil restart — reset the account in MetaMask settings

**Restarting fresh:**
- Kill Anvil and restart (chain resets to block 0)
- Delete `infra/data/local.db` so the indexer resyncs from scratch
- Rerun `02_deploy.sh` to get new contract addresses and update `.env.local`
